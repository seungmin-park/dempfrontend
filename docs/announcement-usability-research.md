# 공고 탐색 실사용 개선 조사 — 2026-11-11

배포 후 직접 공고를 찾으면서 겪은 불편을 정리하고, 여러 채용 탐색 서비스가 같은 문제를 어떻게 푸는지 방문자 시점에서 시장 조사했다. 목록·검색·결과 없음·상세·저장함·비교 화면을 중심으로 봤다. 정렬 비교는 [2026-10-08 조사](announcement-market-research.md)를 함께 참고했다. 서비스 이름·문구·디자인은 옮기지 않는다. 같은 문제를 DEMP의 데이터와 원칙으로 다시 풀었다.

| 실사용 불편 | 조사에서 본 접근 | DEMP 개선 |
|---|---|---|
| 상세에서 '←'로 돌아오면 24건 중 8건만 남음(Playwright 재현) | 번호 페이지라 뒤로 가면 같은 페이지 | 무한 스크롤은 유지하고, history 항목별로 불러온 페이지와 누른 공고를 복원해 포커스를 준다 |
| 결과가 없으면 조건을 한 번에 모두 지움 | 조건별 해제 버튼 + 전체 초기화 | 조건 하나씩 뺀 1건 확인으로 **결과가 실제로 나오는 조건만** 제안한다 |
| 마감 날짜만 있어 남은 시간을 계산해야 함 | 날짜 단위 D-day | 정확한 마감 시각으로 '오늘 18:00 마감'·'N일 남음'을 표시한다. 시각이 정해지지 않은 마감 방식에는 기한을 지어내지 않는다 |
| '공고 목록 8'이 전체인지 불명확 | 전체 수와 현재 페이지 수를 구분 | 전체 개수를 세지 않는 API는 그대로 두고 '지금까지 N개'·'전체 N개'로 정확히 표기한다 |
| 긴 공고는 끝까지 내려야 지원 | 옆에 고정된 지원 영역·링크 복사·캘린더 | 따라오는 지원 바, 링크 복사, 정확한 마감 시각 `.ics`, 운영자 확인일 |
| 지원 준비 자료가 공고와 분리 | 제휴 강의 추천 | DEMP 커뮤니티의 같은 기술 태그 **면접 질문**으로 연결한다 |
| 저장한 공고를 비교할 방법이 없음 | 목록 어디서나 2~4개 비교 | 이미 골라 둔 **관심 공고**에서 비교하고, 선택을 URL에 남긴다. 비교 조회는 조회수를 올리지 않는다 |
| 방금 본 공고를 다시 찾기 어려움 | 기기 저장 최근 본 공고 | 로그인 계정별 기기 저장, 상세 조회에 성공한 공고만 기록 |

상세 열람의 로그인 요구는 `spec.md`의 제품 결정이라 바꾸지 않았다. 구현·검증 기록은 [작업 계획](plans/announcement-discovery-continuity-and-comparison.md)에 있다.
